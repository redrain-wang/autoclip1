# 人物复用与完整冲突提纲

这两项改进用于未来新稿：复用本剧已核对的人物参考，减少换场景后重新猜人；先明确一个冲突的问题、推进和实际结果，再写解说。已有成片和定稿渲染不自动改写。

## 人物资料怎样复用

本机《雍正王朝》已有7名人物、10张参考图。八爷、太子和康熙各补了一种场景或角度；四爷、十三爷、田大人、陈大人保留已有核对图。不同照片共用同一个人物编号，不因换衣服重新建人物。参考库不是模型自行认定的百科，补图仍须有原片、称呼依据和核对记录。

核对分两步：

1. 只提供参考图与场景图，先比较脸，不提供解说稿或台词诱导认人。
2. 加入本场前后台词，逐条判断谁在说话、谁在听、谁被提及。ASR把一段话切成多个短句时，允许同一连续发言共用前后画面；实际换人、缺少中间台词或长间隔会中断这种复用。点名、回应“在”、再提问不会被合为同一个人说话。

取帧跟随台词起止和中间位置，每90秒窗口最多48帧。单张同期画面不能独自证明它是发言者；如果模型把证据类别写成“点名回应”，实际却没有点名，只在多帧与连续对话另有支撑时归为画面/对话推断，不编造点名。

源片观察保存在配置旁的 `output/人物场景/`，相同原片、参考、台词、区间、取帧和模型可跨稿复用。换稿不必从头认人；换素材版本或人物依据会产生新缓存。缓存仍执行当前引用检查。结果中保留原始判断、使用的连续发言范围、引用画面和未知原因，便于追查。

独立运行，不生成视频：

```bash
.venv/bin/python -m autoclip identify-scene /path/to/06.mp4 \
  --transcript /path/to/transcript.json --start 1518 --end 1572 \
  --config configs.production.toml --output output/场景人物核对
```

结果为 `scene-identity-latest.json`。`model_supported`是图片和对话推断得到支持，仍不是人脸识别或声纹认证。未知人物、反应镜头和错配仍可能影响结果。

## 写稿前怎样整理冲突

生产配置和两个长片配置已启用 `conflict_brief = true`。常规生产在选中故事后、起稿前生成提纲；长片 `write-outline` 在既有章节范围内生成提纲，传给各章写稿。独立入口：

```bash
.venv/bin/python -m autoclip story-brief /path/to/06.mp4 \
  --transcript /path/to/transcript.json --start 2270 --end 2610 \
  --config configs.long-yunjian.toml --output output/刑场故事提纲
```

输出 `完整冲突提纲.md` 和 `conflict-brief.json`，包含：

- 主问题和观众在意的原因。
- 按剧情顺序整理的起因、阻力、选择、转折或结果，以及对应台词时间。
- 每处旁白该解释什么，避免只是重复原声。
- 本段实际结尾、还没解决的问题，以及可以删掉的重复或支线。
- 可选的连续原声开场建议；不连续的台词拼接不会被当成一段连续原声。

这是一份编辑建议，不是新的评分关卡。没有转折不强求转折，没有结案不写成已经结案，不规定每集必须拆几条，也不改变用户选择的成片时长。它不自动更改已定章节的镜头和开场；目前也没有实现复杂的自动拆集系统。

字幕旁必须有匹配当前原片的 `source.json`。项目目录外运行时将解释器、素材、字幕、配置和输出写成绝对路径；程序读取配置旁的 `.env`。沿用Go Flash订阅，不自动回退官方付费接口。

## 本轮实际验证及局限

使用第四、六集三个场景，对照了32条已明确归属的台词和3条应保持未知的台词：八爷连续发言、太子回应、康熙接话、田大人与陈大人问答均与本次开发对照一致；未登记人物的三句没有再冒认为四爷。另有“讲”等短句尚未落实，没有把未知算作识别成功。这是针对已知问题的小样本，不能换算成通用准确率。

早期稀疏取帧和逐短句校验拒绝了很多正确归属。最终按台词取帧，并依据完整发言关联图片；修改关联规则后复用相同模型原答核验，没有重抽模型回答直到通过。

刑场提纲能区分暂停行刑、带进宫继续问与最终结案，但真实模型输出仍出现转写错名、说话人混淆、解释过满，以及将分散对白称为连续开场的错误。后者已由引用检查剔除；其他内容仍交给既有写稿和内容核对处理，不能把提纲当作已审核的事实。下一条新片需比较首稿实际修订量，尚不宣称已经稳定达到第四至六集开发样片质量。

本地试验和失败记录在 `output/人物复用与冲突提纲验收/`；图片、字幕、模型响应、参考库和成片均不进入Git。代码和命令不依赖Codex会话，但新机器需恢复自己的本地素材和人物资料。
