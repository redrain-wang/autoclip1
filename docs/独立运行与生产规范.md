# 独立运行与新片生产规范

> 2026-10-18：正式长片使用`制作长片.command`（`series`），短片使用`制作短片.command`（`produce`），两者均一条命令自动制作至导出，并通过`--library`复用本剧人工声纹库。长片目标20分钟、验收18–22分钟；短片目标190秒、验收120–240秒，均始终剧情优先。首次没有库时仅声纹确认需要人工，确认后重复原命令续作。`batch`等旧入口保留历史兼容，不作为新统一生产流程，详情见[README](../README.md)。

## 一条命令完成新片

准备Python 3.12、FFmpeg（含libass）、中文字体、项目依赖和本地.env。源码、台标和提示词都在仓库内；运行时不需要Codex、ChatGPT订阅或图像生成工具。

在项目目录安装：

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python -e '.[mac,dev]'
cp .env.example .env  # 仅首次创建，不覆盖已有密钥
```

Apple Silicon使用mac依赖；其他平台使用cpu依赖并将ASR后端改为faster、模型改为large-v3。

在.env中填写DEEPSEEK_API_KEY和AUTOCLIP_SOURCE_DIR。然后执行：

```bash
.venv/bin/python -m autoclip produce
```

也可使用与长片对称的短片启动脚本：

```bash
# 一个文件：该集最多推荐3个不同的新故事，合格的分别出片
./制作短片.command /path/to/剧名/10.mp4 --library /path/to/registry.json --max-new 3 --output output/短片制作/第十集

# 整个目录：逐集处理，每集分别最多推荐3个新故事
./制作短片.command /path/to/剧名 --library /path/to/registry.json --max-new 3 --output output/短片制作/整剧
```

默认每集本轮最多3个新候选，`--max-new`可设1–6，控制的是故事数而非集数，审核不通过可以少出或不出。此前`--max-new 1`只是单条试跑限制，系统支持同一集多条成片及多集批量。视频、同名封面、清单和最终稿自动导出到指定输出目录下的`成片/`。脚本直接执行到结束，无需Codex逐步操作，不启动额外浏览器服务；重复同一命令可续跑，新批次换`--output`并按历史去重。

长短片统一使用本剧人工确认声纹库，短片增加 `--library`、`--voice-manifest`、`--model-path`、`--voice-python`及可选`--series`。同一输出项目在`short-project.json`记住路径；缺库时自动准备声音确认候选，返回退出码2，人工确认后重跑即可。人物核对不再要求人工脸部锚点：整集扫描、当前库重匹配、字幕关联与逐项画面/问答审核全部自动进行，机器候选不写回人工库。仍可能误判，不能将声纹相似当作身份定论。

长短片制作中停止时，如仍有可提取的人物声音疑点，也会自动生成匿名试听候选并返回退出码2。按日志打开声音确认页，确认认出的角色并点击“保存本轮，返回自动制作”，然后执行原制作命令；程序备份并合并人工参考。待确认期间重复命令不会继续调用模型改稿。长片在原片、字幕、配置、前情等运行条件不变时复用已实配稿及有效分析，重新测时和完整审核，不继承旧批准。只有声音身份需要人工输入，事实与切点修复仍由程序处理。

macOS也可以双击根目录“生成新片.command”。该脚本自动进入项目目录，生产结束后打开新片浏览页。

从任意其他目录执行，需给出已安装的Python和配置文件绝对路径：

```bash
/path/to/project/.venv/bin/python -m autoclip produce --config /path/to/project/configs.production.toml
```

视频、配套封面、最终解说稿与清单自动导出到 `output/新片-长版/成片`。`output/成片` 中的旧成片保持原样。新配置只影响新批次。

当前新片默认云扬（`zh-CN-YunyangNeural`，速度`+8%`），视频底部只显示剧名。需要试听或更换创作配置时使用新的输出目录；旧片不会因改配置自动替换。

制作前会先生成带时间码的分集研究初稿，人物背景只用于消歧，不能证明说话人身份。可用`research`命令单独准备资料，生产会复用同一原片且输入未变的研究缓存。详情见[人物核对与前置研究](人物核对与前置研究.md)。现阶段模型审核仍可能错认人物，不能把流程通过解释为内容完全可信。

## 固定生产步骤

1. 检查素材、密钥、FFmpeg、透明台标和中文字体。
2. 识别素材指纹。相同素材可复制已有转写、抽帧和模型缓存；不复制旧解说稿或逐镜头人工编辑文件。
3. 本地转写对白，结合抽样画面理解整集。原片音频不发送给语言模型，字幕及抽帧会发送给DeepSeek。
   v1.1可通过`--subtitle-layer`为单个素材启用已导出的字幕纠错层，原识别仍保留，改动记录在`transcript-input.json`。不指定时按原识别运行；完整操作和适用范围见[字幕证据核对](字幕证据核对.md)。
4. 读取以前已完成的成片标题、角度和镜头区间，重新寻找未做过的完整故事。默认每集最多推荐3条新故事，可设 `--max-new 1` 至 `--max-new 6`。
5. 每个候选独立检查范围、证据与重复率。不合格候选记录原因，其他合格候选继续生产。不承诺每次都找到足够选题。
6. 每个故事独立编写脚本，按证据核查人物、因果和画面；时间线不合法时自动修订，语义核查最多3轮。
7. 在编码镜头之前合成口播，测量每句声音和全片总时长。少数口播超时先局部缩写并复核事实；问题较多时把完整稿件、具体镜头和实测范围交回编导修复。新片目标190秒，实际验收120–240秒；达到两分钟且故事完整即可结束，不再因低于150秒拒绝。优先10–18秒连续高光原声开场（完整句子可到22秒），随后接解说，原声占比目标约60%，不作硬配额。字数预估允许10%的误差，最终按实际媒体时长检查。解说画面允许约0.71–1.39倍速，单镜头时间匹配允许25fps的一帧舍入误差，原声段保持原速；以增加情节、原声与解释支撑时长，不能靠重复镜头凑长。
8. 烧录字幕、混合原声，配音文字保留标点以控制停顿，显示字幕删除末尾逗号、句号等标点。原声段不显示“听这句原声”等提示文案，保留片源字幕。
9. 按成片序号交替使用白金/朱红白水印；同一条视频始终使用同一款，其封面使用相同台标。
10. 完整解码成片，核对时长与音视频轨，生成独立封面，导出视频、封面、稿件、时间映射和运行记录。

## 自动重试与失败处理

模型和配音网络请求均有有限重试；每个新故事初次生成后，默认最多3轮针对性修复，可用配置项 `repair_attempts` 设置0–5轮。编导生成与语义审核内部仍有有限修订次数，所有实际模型请求受单集 `max_api_calls` 上限约束。最终仍未达内容标准的候选记录到 `rejected.json`，其他合格候选继续生产。基础设施或服务故障记录到 `failures.json`，不会通过重新编稿来重试这些故障。返回码0表示本批处理结束（允许淘汰候选），1表示存在未解决的运行故障；已成功成片仍会导出。零成片时终端明确列出各候选原因。

故事目录内 `voice-preflight-*.json` 保存编码前的实测时长及问题，`voice-local-repair-*.json` 保存局部缩写与事实审核结果，`attempt-*.json` 保存完整修复依据。常规重跑可能更新同编号的尝试记录；需要比较不同版本时，应事先保存验收快照。

编导与修复新增[时长预算](时长预算与修复.md)：使用实测语速、原声总量、未使用的完整对白及相邻镜头空余范围，帮助分配画面和解说字数。预算只提供修复依据，不能直接通过时长检查，也不会自动用空镜或重复画面补长。

重复同一命令会重用匹配当前输入的选题、模型、配音与渲染缓存。已完成的新片单独记入 `completed.json`；仅在当前声纹、字幕、配置、实际成片和审核画面均匹配时跳过，即使在包装后中断也能从完整记录恢复清单。声纹或核对规则变化时重新测时核验，旧媒体保留；旧锚点流程或过期核定不能直接恢复为当前交付。若需要开启另一个批次，可传 `--output output/另一个批次`，其他已完成批次参与历史去重。

`--stage scout` 只检查新选题；`--stage plan` 只生成并核查脚本。`selection.json` 列出接受的候选，`selection-rejected-*.json` 保留淘汰原因；候选通过不等于最终视频通过，最终产量看 `results.json` 与批次 `batch.json`。

独立运行仍依赖有效的模型余额、网络、TTS服务、素材磁盘和本机工具。服务不可用时程序会重试并给出错误，不能保证外部服务永不失败。当前通用Edge TTS不提供生产服务SLA，长期大规模生产可替换付费TTS适配器。

## 验收边界

运行流程不依赖Codex，质量门槛也由代码执行。确定性检查能拦截越界、错时长、重复素材、坏媒体等问题；模型语义审核仍可能遗漏剧情细节。本版本不把“能无人值守运行”当成每条内容都无误的保证。

此次验收使用项目目录外的独立Python进程，移除Codex环境变量，实际调用Flash和TTS生产新故事；旧成片与封面用SHA-256校验保持不变。具体新产量、时长和检查结果记录在本机 `output/新片-长版/验收报告.json`。
