# 加长解读与配音

长解读先确定一个可以用原片回答的总问题，再把相关冲突串成章节。本次第四集试片的问题是“四爷追债，难的究竟是什么”：接差与用人 → 太子的背书和名单 → 当众立规矩 → 资历和亲缘 → 一两银子 → 用途与承诺 → 功劳与面子 → 名单遗漏 → 兄弟关系与同一标准。

参考用户提供的18分46秒样片，学习其问题、证据、选择代价和因果展开，不复制解说原句或模仿其声音。先保留连续原声开场，再交替使用对白与分析。分析需要推进问题：谁想把什么变成例外，执行者有什么选择，哪种代价由谁承担。对指责和转述保持来源限定，不能把它们当作已核实的内心与事实。

## 当前能力和限制

`configs.long.toml`显式启用长片，目标17分30秒、实配验收15–20分钟，支持最多96段镜头。普通生产仍是120–240秒，未因加长试片放宽。

加长入口接受绑定原片版本、固定镜头、字幕证据及逐段写作意图的提纲。程序按章节写稿，保存失败稿和有限修订记录，再配音实测。字数只能粗估；上述旧长片配置的真实配音加原声必须落在900–1200秒内。文字过短时，可从原有口播画面范围内选子区间；不能替换原声、凭空延长故事、自动批准稿件。

此阶段是**开发核对试片流程**。提纲和最终稿包含开发参与，正常无人复核的人物审核还有错配与误拒待解决。`produce`和常规批量编导拒绝长片配置，避免用短故事约束反复付费尝试长稿。不能宣称输入任意新剧就已能稳定自动产出15–20分钟的正确解读。

在项目根目录，新提纲先写稿再测时：

```bash
.venv/bin/python -m autoclip write-outline /path/to/episode.mp4 \
  --config configs.long.toml --outline /path/to/outline.json \
  --transcript /path/to/transcript.json --output output/另一条长片

.venv/bin/python -m autoclip measure-plan /path/to/episode.mp4 \
  --config configs.long.toml --plan output/另一条长片/plan.json \
  --transcript /path/to/transcript.json --output output/另一条长片
```

`transcript.json`旁的`source.json`必须属于同一原片版本。提纲包括`source`、`title`、`angle`、`hook`和`chapters`；每章有`title`及`beats`，镜头含`id/mode/start/end/evidence_ids/allowed_evidence_ids/instruction`，口播还含`target_chars`。允许引用不得包含当前镜头之后才开始的字幕。提纲本身是创作方向，不是剧情事实证据。

测时成功会生成`plan-timed.json`和`timing-preflight.json`，仍标为未核对。修改后需重新核对人物、事实、推理和剪辑，并生成绑定最终计划、字幕和画面哈希的逐段核对记录，才可使用`render-sample`。不要再次执行`write-outline`覆盖已核定的稿件。

完整自动初稿先保存为`draft-plan.json`，精修失败也可以定位问题，不必重新请求各章。章节字数范围为预算的45%–140%，允许短过渡保持简洁；全片900–1200秒与配音/画面匹配仍以真实音频检查，不能用放松字数限制凑时长。章节缓存按写作规则绑定，精修检查器内部变化不单独触发所有章节重写。

## 云扬接口修复

2026-10-12本机旧Bing接口连续返回403。用户提供`api.msedgeservices.com`后，实际验证云扬合成成功。仅更换域名会得到404；新接口为：

```text
wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1
```

它使用`Ocp-Apim-Subscription-Key`查询参数，而旧接口使用`TrustedClientToken`。两者使用的是edge-tts库内的公开客户端令牌，不读取用户的大模型或Azure密钥。接口变更背景见[edge-tts上游问题记录](https://github.com/rany2/edge-tts/issues/421)。此处结果来自本机实际请求，并不保证免费通道一直可用。

默认`tts="edge"`、`edge_endpoint="msedge"`、`voice="zh-CN-YunyangNeural"`、`tts_rate="+8%"`。端点覆盖只在请求期间生效，加锁并恢复库状态，不永久修改安装包。合法的原有同文稿/音色/语速音频缓存继续复用。需要诊断旧通道时可显式设`edge_endpoint="bing"`，不会自动换声或切换付费服务。

如免费接口再次不可用，可**明确选择**`tts="azure"`并在本地`.env`设置`AZURE_SPEECH_KEY`和`AZURE_SPEECH_REGION`，仍可用云扬，但需单独的Azure Speech资源；不能拿Go或DeepSeek密钥替代。`tts="macos"`则使用本机声音，可配置`macos_voice`和`macos_rate`，不是云扬。失败会保留稿件和已完成的音频缓存，重试从缓存续作。

写稿默认使用OpenCode Go的`deepseek-v4.1-flash`，本次七处文本纠错曾使用同订阅的`kimi-k3`。渲染固定稿件不发起模型改写。用量记录区分本轮实际请求模型与历史缓存累计token，缓存总量不能当作本轮费用。

## 自动章节提纲试验

新增 `plan-outline` 可先依据本集字幕、最近三集资料和完整冲突提纲，安排章节、前置原声与镜头，再交给 `write-outline`。它是显式试验入口，未接替常规生产或自动批准成片。

```bash
.venv/bin/python -m autoclip plan-outline /path/to/episode.mp4 \
  --transcript /path/to/transcript.json --config configs.long-yunjian.toml \
  --output output/新片提纲
```

可选 `--start/--end` 指定选题素材范围；`--notes /path/to/核对备注.txt` 传入已查清的人物与事件归属。已有章节时可传 `--structure`，文件须含当前原片的 `source` 标识和 `structure` 对象；结构字段见 `autoclip/planning.py` 的 `Structure`，不能套用另一集的时间码。

命令先保存模型原答，再检查章节重叠、镜头长度、引用后文和重复高光等问题。章节结构最多修正一次，镜头表最多修正一次；失败保留具体错误并退出，成功才生成 `outline.auto.json`。建议每次新试验使用独立输出目录，不能把旧目录内的文件当成本次成功。现有 `outline.json` 不由这个命令覆盖。通过时间检查仍需人物、事实、观点和实际配音核对。

第七集真实试验未通过自动提纲验收：章节及镜头仍有重复高光、提前引用后文、超过40秒等问题。最终采用开发修订提纲，不把人工纠错后的成片计为自动初稿成功。新入口的价值是保留可定位、可续作的初稿和失败记录，尚不能保证任意剧集无人干预出长片。

## 写稿前检查镜头表

`write-outline` 现在在读取前情、生成冲突提纲和调用写稿模型前，检查手工或自动提纲的来源、证据与完整镜头时间线。可独立运行只读检查：

```sh
.venv/bin/python -m autoclip check-outline /path/to/episode.mp4 \
  --outline /path/to/outline.json --transcript /path/to/transcript.json \
  --config configs.story-yunjian.toml
```

检查复用既有镜头规则：顺序、重叠、前置高光避让、原声开场、证据位置与置信度；同时检查空章节、重复编号、直接引用和允许引用是否一致。失败时返回非零退出码，不调用模型、不生成或修改文件。配置须与该提纲的开场方式一致。

此时尚未写口播，不使用占位文字估算成片时长；写稿后的预计时长与配音后的实测检查保持执行。通过只表示结构合法，不代表人物、剧情或观点已经核实。历史提纲可能保留被后续定稿纠正的问题，检查失败不等于已核定成片失败，也不会改写已交付版本。

## 整剧自动长解说入口（2026-10-18）

日常自动生产现在使用 `series 素材目录 --output 独立项目目录`，默认通用配置为 `configs.series.toml`。项目自动记住剧名、素材清单、模型配置和声纹路径；只在首次没有人工声纹参考时准备试听候选并返回待确认。声纹确认完成后重跑原命令，其他步骤均由系统处理。

新入口直接执行：研究与前情 → 逐章预算和镜头编排 → 写稿 → 实配测时 → 自动内容/人物审核 → 局部修复 → 冻结稿件渲染 → 技术检查与包装导出。顺叙 `original` 和前置高光 `original_teaser` 都支持；自动提纲已按失败章节修复，不再要求人为整理完整镜头表。机器审核仍可能误判，失败后不会自动生成“人工已确认”记录。

`automatic-review.json` 绑定原片、字幕、最终稿、声音证据和实际核对画面；`development-review.json` 仍只属于旧的人工核定复现路径。旧 `render-sample` 的约束没有删除，但它不参与新 `series` 流程。

产物写入项目内的 `episodes/成片` 和 `episodes/index.html`。各阶段有输入及产物指纹，复跑只有匹配时才复用。声纹库更新后自动标记影响范围，重新关联与核对；旧运行目录保留。失败集保存原因并继续后续集，达到重试上限不再无限改稿。

本轮自动化范围到本地导出，不包含平台发布。完整流程图、命令与运行状态见 README。
