# 人物归属独立检查与文案试验

本流程把“主张的行为属于谁”单独检查，不再只依赖整稿审片。它已接入命令行和生产流程，不依赖Codex会话。2026-10-13增加多角度人物参考、先认脸再逐条归属以及原片观察缓存，见[人物复用与完整冲突提纲](人物复用与完整冲突.md)。**目前是保守拦截机制，不是已达到可靠准确率的人物识别系统。** 第四集试跑仍出现田大人与四爷的画面错配，因此尚不恢复批量出片。

## 核对顺序

1. 从经过核对的原片画面建立角色参考：姓名、别名、身份依据、核对者、原片版本、图片哈希及裁剪范围。初始参考需要核实，不能让模型把自猜结果直接标为已核实。
2. 在看到解说稿之前整理本场画面与发言记录。把参考标为R编号、场景帧标为F编号，未知人物保持未知。引用帧必须在对应发言时间附近；几十秒前出现过一张脸不算当前发言证据。
3. 对标题、角度、钩子和每段口播分别提取人物主张，区分说话人、行为者、被问者及被提及者。已点名的被问者不需要说出提问者的台词，但主动行为不能借此例外通过。
4. 主张与独立发言记录冲突、证据不足、引用不存在、审核漏项时拒绝。有限修稿仍不合格则结束该候选，不把审核猜测的新姓名直接替换进稿。
5. 配音缩写后的实际文字再次核对；复用渲染缓存时也检查缓存中实际口播，防止只查原计划而漏掉变化。

“独立”指先看原片、再审文案的输入顺序与职责分离；目前仍使用同一Flash模型，误差并不相互独立。静帧无法证明口型同步，也没有完整声音身份识别。程序能检查引用和一致性，不能证明模型认脸正确。

## 配置与本地资料

`configs.production.toml`启用：

```toml
identity_gate = true
identity_registry = "output/人物锚点/registry.json"
```

路径按配置文件所在目录解析，可用`AUTOCLIP_IDENTITY_REGISTRY`指定其他本地位置。明确配置的文件丢失时直接报告错误，不静默退回无画面参考。设置`identity_registry`为空时可以尝试明确点名与回应，但不能只凭“儿臣”等非唯一称呼放行。

本机已有7个人物、10张参考图：八阿哥、太子、四爷、十三爷、康熙，以及第四集原片中的“田大人”“陈大人”。后两者暂用原片称谓，不把ASR里可能写错的完整姓名变成标准名字。这是开发阶段结合原片和称呼链核对的参考集，不是全自动生成的人物百科。

同一人物可在`references`数组中追加其他角度；每张仍须独立提供`status/reviewer/basis/source/image/image_sha256`，可加`crop`。未经核对的补图不参与匹配。

每条参考的结构如下（占位示例不能直接用于生产）：

```json
{
  "series": "作品名",
  "anchors": [{
    "id": "character-1", "name": "已确认姓名", "aliases": ["已确认称谓"],
    "status": "reviewed", "reviewer": "核对者", "basis": "点名、回应及原片时间的依据",
    "source": {"path": "原片绝对路径", "size": 0, "mtime_ns": 0, "sample_sha256": "原片版本指纹"},
    "image": "frames/character-1.jpg", "image_sha256": "图片SHA256",
    "crop": [0, 0, 200, 200]
  }]
}
```

图片哈希及原片版本变化会导致拒绝；不要改哈希来绕过核实。本地原片、参考图、详细转写、模型响应与稿件均在忽略的`output/`内，不推送Git。新机器需自行恢复这些本地资料及素材，并核对路径和版本；克隆代码不包含它们。

## 独立命令

在项目目录运行，路径换成实际素材、稿件和字幕：

```bash
.venv/bin/python -m autoclip identity-audit /path/to/03.mp4 \
  --plan /path/to/plan.json --transcript /path/to/transcript.json \
  --config configs.production.toml --output output/人物归属复核

.venv/bin/python -m autoclip compare-scripts /path/to/04.mp4 \
  --transcript /path/to/transcript.json --start 1000 --end 1230 \
  --config configs.production.toml --output output/文案对比
```

字幕同目录的`source.json`必须匹配当前原片，防止拿另一集或另一个版本的字幕核对。项目目录外运行时，使用解释器、配置、素材、稿件、字幕和输出的绝对路径；配置目录旁的`.env`会被加载。

`identity-audit`不改旧计划或影片，逐片输出`identity-latest.json`，详细报告含输入指纹、模型原答、逐项主张与拒绝原因。全部通过退出0；任何拒绝退出1。场景表、图片及请求均有缓存，但缓存命中仍重新执行当前程序校验。

`compare-scripts`只比稿，不生成视频。A描述剧情，B解释选择、代价、结果与其他解释。B的口播正文至少需要两处分析和一处推断边界；审核必须摘录真实口播，不能引用`interpretation`备注得分。内容评价仍来自模型，不能据此宣称解读水平已达到参考作者。

每版最多自动修订`min(repair_attempts, 2)`轮，保存每次`attempt-N/result.json`。修稿要求删除无法落实的次要说法，不靠更换姓名或泛称规避。输出`comparison.json`和`两版解说稿.md`；只有两版人物及分析检查均通过才退出0。即使退出0，稿件仍标记`renderable=false`，还需完整语义、时间线、配音和影片验收，不能直接拿研究载体渲染。

## 当前真实验证与下一步

- 第三集简短正例：八阿哥提出交出户部，随后康熙问太子意见，最终通过。它是专门的归属测试，不是满足时长要求的新成片。
- 第三集历史错稿：最终拒绝。不同尝试有明确错归判断，也有无法核实；拒绝一个错稿不等于独立认出了所有人物。
- 第四集1000–1230秒A/B试验：两版各完成最多两轮修订，最终未通过。出现画面错配、泛称未落实及分析证据不足；后续稿件未作为合格影片发布。
- 相同提示体系仍可能把正确句子拦下，或漏掉错误。接下来优先拆小画面匹配任务、区分被指责对象与实际发言者，建立包括未知角色与反应镜头的固定验收集；不以反复重跑直到偶然通过作为验收方法。
