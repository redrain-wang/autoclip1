# 自动影视解说：先理解，再表达，最后剪辑

独立命令、长片时长规则、增量去重及断点恢复的具体操作见 [独立运行与生产规范](独立运行与生产规范.md)。

## 1. 判断可行性

技术上可以做到从整片输入到批量成片无人值守。难点不是拼接接口，而是三个问题：是否理解了真实剧情；是否有一个值得说的观点；画面、原声和解说是否在同一节奏上。

“完全自动生产”与“自动得到爆款”不是同一承诺。前者可以工程化实现；后者受作品、受众、文案、声音和分发影响，需要真实样片和反馈。当前系统是可运行的第一版，保留每个中间产物，方便从样片反推改进。

## 2. 证据层：先建立可追溯的剧情事实

优先读取匹配版本的字幕；否则在本地对音轨每五分钟转写一次，得到带时间码的对白。给每条对白一个ID。原片指纹、模型、识别提示和字幕内容共同决定缓存版本。

每五分钟抽六张带绝对时间标签的画面，与同区间字幕一起送给多模态模型。记录发生了什么、画面实际出现什么、人物与冲突、可供展开的候选，以及不确定性。片头歌词、片尾和低信息段不作为故事依据。

选择成片后，再抽取每个剪辑段的中间画面复核。当前是稀疏抽样，不是逐帧视频理解；一闪而过的表情、无对白肢体笑点、画外人物判断仍可能遗漏。针对这类内容，下一版应加入镜头检测、运动强度与更密集的视觉复核。

## 3. 选题层：选择一个完整的小故事

高光不等于音量大或打斗多。每个候选都评估冲突、共鸣、幽默、反转、故事完整度（0–10）。模型结合这些评分、类型和整集事实选题，不单独按某个分数机械取最大值。

| 类型 | 值得讲的核心 | 容易犯的错 |
| --- | --- | --- |
| 历史权谋 | 一句话背后的利益与制度约束 | 用后续剧情反推当下动机，假装角色无所不知 |
| 家庭情感 | 角色为什么委屈、妥协或决裂 | 强行站队、为情绪捏造事实 |
| 喜剧 | 铺垫、错位、反差与兑现 | 提前解释笑点，破坏包袱 |
| 悬疑 | 信息差和观众认知变化 | 剧透答案，或制造原片不存在的悬念 |
| 动作冒险 | 目标、障碍、代价和选择 | 只有快切，缺少人物目标 |

每条只围绕一个角度，观众不需要看过全集也能理解前因后果。不同成片不得大量复用同一段剧情。整季文件夹顺序处理，传递最近已处理集数的摘要；剪辑素材仍以当前集为单位，尚未实现跨集蒙太奇与全季人物知识图谱。

初始每集两条是固定数量配置，不是看点总数。`clips=0` 启用按质量选数量：模型选择0–6个有充分证据、独立角度和完整因果的故事，无合格选题可以不出片。既有证据、重复率和成片检查继续生效。

## 4. 写稿层：用“具体矛盾—必要背景—原声证据—观点兑现”组织

开头用一两句具体冲突吸引注意，而不是“今天带大家看某某”。中段只补观众需要的背景，把关键话留给角色本人说。原声前提示看点，原声后解释含义。最后回应开头的矛盾，给出来自本段事实的观点。

《雍正王朝》适合问：一个人为什么不愿接这项差事？说出这句话会让谁承担代价？一次看似正确的选择为什么仍使人陷入困境？这些是写作方向，只有素材提供证据时才能落实成具体结论。

模型必须输出结构化的剪辑脚本：每段原片起止秒数、解说/原声模式、对应字幕ID、解说文本、画面选取理由。禁止把猜测写成明示事实，不能靠记忆补原片没有的情节。

## 5. 节奏层：原声与解说轮流承担信息

原声段让观众直接感受人物的气口与表情；解说段负责引导、关联和表达观点。两者各有位置。每条至少保留关键原声，禁止解说覆盖一切。

先将模型选中的较长剧情范围，围绕引用的对白编译为适合短口播的镜头；原声边界贴合完整字幕句。编译后的镜头才进入画面和事实复核。解说可以在紧接原声的反应镜头上点破含义，因此允许引用前15秒内的对白，不能无限回溯或拿未来对白作证据。

再按合成语音的真实时长安排镜头。允许适度调整画面速度（短片约0.78–1.39倍，新增长片约0.71–1.39倍），超出范围时自动缩写或扩写口播，再复核是否引入新事实。原声段保持原速。不会用无限定格或循环镜头补满声音。

字数只能粗估口播时长，编导阶段采用较宽的异常范围，成片阶段再用真实合成声音和媒体时长严格校验。长原声可以在字幕句子边界拆成相邻镜头，拼接时保持连续，不因单镜头长度限制丢掉对白。

竖屏保留完整原画幅，使用暗化柔焦背景，上方标题，下方解说字幕。这样避免盲目裁中间导致两人对话只剩一个人。后续可以加人脸追踪裁切，但应将镜头叙事优先于占满屏幕。

品牌包装独立于脚本与配音：在已完成的视频左上角叠加“爱大片儿”透明台标，音轨直接复制。每条同时输出独立封面，以该条实际剪辑区间内的原片画面为底图，配相同标题与品牌标识。封面选帧目前依据亮度、对比度和清晰度，不宣称理解人物表情；它不额外创造人物或事件。

解说期间原声降低到0.035倍，以避免对白干扰；这里没有做音乐/对白分轨，因此残留原对白仍可能听见。最终做响度归一化与峰值限制。配音使用通用合成声，暂未实现带情绪标记的付费语音服务或角色声音复刻。

## 6. 质量层：机器能检查的严格检查

**确定性检查**：时间越界、段落倒序/重叠、虚构字幕ID、证据不在画面区间、重复选题、配音与画面时长不匹配、成片音视频轨缺失、完整解码失败、时长严重偏离目标。

**模型审查**：人物与因果是否有根据，观众是否看得懂，开头是否兑现，画面是否支撑解说，原声切点是否完整。每条分别进行最多三轮审查。仍有争议时，默认记录失败；显式设置 `AUTOCLIP_ADJUDICATION_MODEL` 后，可用同一DeepSeek官方接口上的指定模型做最多两轮独立文字裁决。它不接收图片，也不声称看过画面；实质疑点无法解决则继续阻止出片。

开发验收允许抽样检查并记录问题。在对应集的 `editor_notes.json` 中保留反馈、修改目标和来源，模型按反馈修改后仍需通过审查。正常批量生产不需要该文件。首集样片使用过这一人工反馈环节，不能将其称为全程零人工干预的质量验证。

模型审查并非独立人工认证；同一模型可能共享盲点。ASR可能误认人物名，抽帧可能漏掉表情，句内字幕是近似时间分配。首次使用新剧种，建议看一条样片再扩大产量，以便调整识别词表、风格和语速。

## 7. 批量生产和成本管理

转写按五分钟缓存，模型请求按输入缓存，配音按文本和声音缓存，镜头按版本缓存。改变配置会产生新渲染目录，不覆盖历史成片。每集加文件锁，避免重复任务同时写入。同一批中失败隔离，任务完成后可直接重跑。

每次模型调用有超时、有限重试和次数上限；记录输入/输出token，不臆测价格。粗看脚本后再渲染可用 `--stage plan`。批次按集顺序执行，分段分析最多三路并发，避免本机GPU内存被多个识别模型争用。

大规模生产的下一步：数据库任务队列、对象存储、GPU识别工人、付费TTS适配、独立模型交叉审片、字幕强制对齐、全季人物事件索引，以及根据完播率校准选题与钩子。当前没有实现这些基础设施，也没有自动发布到短视频平台。

批量发布前需确认素材和改编使用授权；当前程序只在本地生成文件。
