# 人工试听建立角色声纹库

先准备前两集，再打开本地声音确认台。CAM++ 只提供相似声音分组；角色名由人试听后确认。没有固定为十组，因为路人和同一角色的不同声音状态都可能产生额外候选组。

## 安装与准备

建议使用单独环境，避免影响现有转写环境：

```sh
uv venv --python 3.11 .venv-voices
uv pip install --python .venv-voices/bin/python -e '.[voices]'
.venv-voices/bin/python -m autoclip voice-prepare /path/to/01.mp4 /path/to/02.mp4 \
  --series 雍正王朝 --output output/声音确认/雍正王朝 \
  --transcript output/第一集/transcript.json \
  --transcript output/第二集/transcript.json
.venv-voices/bin/python -m autoclip voice-review --output output/声音确认/雍正王朝
```

每个 `transcript.json` 同目录必须有匹配原片的 `source.json`。不提供 `--transcript` 时走现有字幕/ASR 流程（对应 MLX 或 faster-whisper 依赖须另行安装），不重复构建一套转写逻辑。可用 `--model-path` 指定本地 CAM++ 模型目录；未提供时从 ModelScope 下载。声音只在本机提取和试听。

## 试听与确认

1. 左侧按样本数量排列候选声音，通常先处理出现较多的声音即可。
2. 每段显示原片文件名、开始/结束时间、字幕以及音频播放器。播放后可勾选“已听，选中确认”。字幕是定位提示，可能有识别误差。
3. 需要时点击“看前后画面”，播放包含前后各约 3 秒的原片片段。镜头中的人仍可能是听话者。
4. 勾选确定属于同一个人的片段，填角色名并确认。不同声音组填写同一名字会合并为同一角色。
5. 无名角色单独标记，不将所有路人合并为一个声音。音乐、多人混说、错切片段可以排除。没把握的保持待确认。
6. 可撤回已确认片段，或重新命名。只有逐段明确确认的样本进入声纹库，其他组内成员仍待确认。

可以只确认少量清晰样本，不必处理几百条候选。每位主要人物建议先收集来自不同场景的几段清楚发言；数量是工作建议，不是准确率保证。

## 保存位置

- `manifest.json`：原片指纹、精确时间、字幕、CAM++ 特征及机器候选组。
- `review.json`：逐段人工确认、无名角色、排除及待确认状态。
- `registry.json`：仅包含人工确认的具名角色声纹，可供后续比对。
- `history/`：每次修改前的确认记录，便于恢复。
- `cache/`、`media/`：音频、特征缓存和按需生成的试听/画面片段。

确认内容由本机服务写入文件，不依赖浏览器本地存储。保存有版本检查，避免两个页面覆盖彼此。服务默认仅监听 `127.0.0.1:8766`。重新打开启动程序即可继续，按 Ctrl+C 停止服务。原片版本改变时拒绝复用旧位置。新增集数或修改候选参数时用新输出目录保留旧人工记录。

## 后续剧集比对

为后续剧集运行 `voice-prepare`，使用独立输出目录，然后：

```sh
.venv-voices/bin/python -m autoclip voice-match \
  --library output/声音确认/雍正王朝/registry.json \
  --candidates output/声音确认/第三集/manifest.json \
  --output output/声音确认/第三集/匹配候选.json
```

模型权重和剧名必须匹配。每个角色取最相似的最多三个已确认参考分数的均值，再比较第一、第二候选。默认余弦分数阈值 0.65、分差 0.10 是可调初始值，并非概率或经过本剧校准的标准。低分或接近时保留未知。

声纹已用于第八、九集实际制作：以第23版人工库比对缓存音频，候选结合原片称呼、连续问答和画面核对，通过人物备注与开发审阅记录参与写稿和定稿。两集均出现三阿哥被误列八爷候选，核对后纠正，未回写人工参考库。

新增 `series` 整剧入口已自动读取本剧人工库和声音特征清单，按当前库重新比对并关联字幕，再结合原片画面和问答进行自动审核。参考库变更会使下游自动审核失效，保留旧运行并重做新版本。旧 `produce` / `write-outline` 分步入口的行为保持兼容；完整自动制作请使用 `series`。独立标注样本的误认率和未知比例仍需持续评估，不把候选直接升级为确定归属。

## 当前边界

本版复用已有字幕时间切候选片段，不把相邻字幕直接拼成同一人。选取 2.2–12 秒的字幕段，试听/声纹部分最多 8 秒，过短或过长条目跳过；不代表覆盖全部对白。字幕可能跨说话人，也可能含配乐或重叠发言，本版没有执行重叠语音分离或唇音同步检测，故候选必须人工听取。配音演员一人分饰多角时，声纹无法单独决定角色。主要人物声纹库也不能代替“谁做了什么”的剧情核对。

准备时可用 `--skip-start 秒数`、`--skip-end 秒数` 排除片头片尾，默认均为 0。已为本机《雍正王朝》前两集设置 `--skip-start 154`，排除已核对的片头歌字幕。各剧、各版本的片头长度不同，不能通用套用。试听分组默认余弦阈值为 0.50，便于整理候选；它不同于后续角色匹配的 0.65 阈值，组内仍可能混入其他人。

## 什么时候可以停止确认

首页现在展示人物建档进度，而非要求清空全部候选组。每位人物有 3 段已确认参考时显示“本轮够用”；这是初次试比对的数量建议，并非准确性认证，也不证明主要人物都已覆盖。只要你关心的人物已有参考，就可以完成本轮，少于 3 段也允许先试用。

“完成本轮，开始自动比对”会保存完成状态，并生成 `匹配候选.json`。仅比对仍待确认的片段；人工确认、无名角色、排除记录不改动。自动匹配不会进入人工参考库。低分或候选接近时继续保持未知。以后修改确认会取消旧的完成状态，重新完成本轮即可生成更新后的比对结果。

已经匹配到已知人物的片段不会进入新人物推荐；已确认过人物或无名角色的组也从优先建档列表移开，其中未识别片段仍保留待核验，不会整组推定身份。可选推荐一次最多显示 5 组；全部声音仍可在“全部声音（排查用）”找到。

## 比对效果诊断

`voice-evaluate --library 声纹库路径 --output 验证报告路径` 对比 0.65 和 0.60 两个门槛，固定分差 0.10，输出三种诊断：逐段留出（同时去掉同源重叠及相邻 8 秒的片段）、整集留出、整个人留出。缺少该人物独立参考的识别试验会跳过，报告列出测试及跳过数量。整个人留出用于观察是否把库外声音误认成库内人物。

这些参考是人工挑选的小样本，参数对比属于开发诊断，不能作为独立测试集的准确率，尤其不能把第三集匹配数量当作正确数量。默认门槛仍为 0.65；0.60 可通过 `voice-match --threshold 0.60` 输出到独立文件作试验，核验前不提升为标准归属或改写人工库。

## 跨集补充人工参考

新剧集的人工确认保存在该批次自己的 `review.json` / `registry.json`。用 `voice-merge 第一批/registry.json 新批次/registry.json --output 合并库.json` 生成合并声纹库，后续 `voice-match --library 合并库.json ...` 即可使用跨集参考。

合并只接收人工确认样本，保留父库版本，重复片段去重；同一片段姓名或来源冲突、同批次不同版本会拒绝合并。修改/撤回原始确认后需用最新各批次库重新生成合并库，旧的合并文件不会自动同步。

已确认的样本出现在待比对批次时，结果标记 `human_confirmed`，与自动 `suggested` 和 `unknown` 区分；不会把标准样本匹配自身当作自动识别成功。

## 按人物名单查缺补漏

`voice-gap-prepare --plan 补录计划.json --library 已有合并声纹库.json --output 新补录目录 --model-path 模型目录` 按显式人物名单提取短片段。计划包含 `series`、`scope`、`targets`；每个人物有唯一 `id`、`name`、`aliases`，可附 `candidates`（原片 `video`、对应 `transcript`、`start`、`end` 和 `basis` 选择依据）。候选姓名只是线索，仍需人试听确认。

补录页使用已有库的固定快照计算人物覆盖，显示“已确认 / 名单总人数”和缺失姓名。已有角色不再重复要求确认；每个缺失角色先试听一个主候选，需要时换备选。单段确认后立即保存、计入该角色，但备选不会连带入库。没有合适候选或候选已排除的角色仍保留缺口。名单尚有缺失时不能宣称补齐。

补录目录 `registry.json` 仅保存新增人工确认，`registry.expanded.json` 合并原有参考与新增确认。基础库快照为 `baseline-library.json`，其指纹绑定当前补录批次；若原有确认被撤回或改名，应基于最新基础库准备新批次，不能继续沿用旧快照。

本机当前补录页为 `http://127.0.0.1:8768/`，当前前七集的优先名单为 13 位，原有 7 位，待补太子、邬思道、张廷玉、李卫、田文镜、十四爷。这个有限名单用于当前处理范围，不等于全剧人物百科。双击 `听声音认人物.command` 会优先打开该补录页；已启动时直接复用页面。

## 整季声纹扫描

```sh
.venv-voices/bin/python -m autoclip voice-scan-series /path/to/series \
  --library output/声音确认/人物补录/registry.expanded.json \
  --output output/声音确认/全集扫描 \
  --model-path /path/to/campplus --vad-path /path/to/fsmn-vad
```

输入可为单个视频或剧集目录。`--model-path`、`--vad-path` 可省略，程序按模型标识查找或下载本地缓存。

`series` 在已有人工库、未显式提供特征清单时，自动使用这条全片扫描路径；建档试听候选仅用于选取人工参考，不再作为默认生产覆盖。自动生产保持相似度0.65、分差0.10，不降低门槛凑识别率。扫描失败会记录错误，续跑时重试失败部分，不能使用部分扫描结果完成审核。

该路径不需要全季字幕：对每集完整音频做 FSMN-VAD 语音检测，再按 1.5–3 秒窗口提取 CAM++ 特征，输出逐集时间位置与角色候选。过短回复、静音不建立声纹；片头、片尾也扫描，但不优先用作人工参考。VAD 不等于说话轮次分割，背景音乐和多人重叠仍可能影响结果，输出均是候选。

每两分钟保存特征缓存，每集保存独立结果。进程中断后使用相同参数重跑可接续；素材、模型或参考库改变时须使用新输出目录，以免混用。进度为 `scan-progress.json`，全季汇总为 `scan-summary.json`，逐集结果位于 `episodes/`，全集带声纹特征的清单为 `manifest.json`。音频缓存约每小时 115 MB，扫描无需向外部模型发送原片。

使用分批聚类整理未命名声音，内存随样本量近似线性增长，不对全季计算完整的两两距离矩阵。聚类分组不等于角色；高频只是人工选样线索。

完成全季后可导入少量优先样本：

```sh
.venv/bin/python -m autoclip voice-import-discovery \
  --scan output/声音确认/全集扫描 --output output/声音确认/人物补录 --limit 12
```

导入保留已有人工记录，更新批次版本，并准备来自不同集数的代表声音；不自动为聚类填角色名。补录页输入实际人物名称后，只将当前明确确认的片段加入标准库。原有机器匹配结果需要用新合并库重新比对后才更新；已有特征无需重提取。当前角色很少参考时，优先补清晰、多场景样本，不能把机器猜测全部回灌成标准答案。
