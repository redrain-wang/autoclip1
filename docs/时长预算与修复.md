# 实测时长预算与修复

根据2026-10-11用户调整，新片按120–240秒验收，默认目标190秒。目标不是必须凑够的配额：如果故事没有足够事实、原声与画面，候选可以淘汰。

编导生成初稿之前，程序提供故事原片范围、目标时长、参考原声占比和总解说字数。首次语速只是估算；配音预检之后改用同一稿件的真实语音秒数与有效字数计算语速，重新分配剩余时长。标点不计入字数，真实停顿仍计入声音时长。

修复报告的`timing_budget`提供：

- 距离最低时长和目标时长分别还差多少秒，或超过上限多少秒。
- 现有原声总量、未剪入的原片范围，以及完全落在这些范围内的可靠字幕。
- 每段口播至少需要的画面长度、相邻镜头之间可用的范围，是否必须改写或重新分配相邻原声。
- 不重复画面、按最大允许慢放计算的数学上限。它只是上限，不表示全部画面都适合使用。

报告不直接修改镜头，不把空余画面自动补进片子，也不将跨越已用镜头的半句对白列作完整备用原声。编导必须判断备用片段是否能补充必要背景、冲突或结果，再经过时间线、语义审核和真实配音预检。原有实测时长、声音与画面匹配、事实和重复率门槛不变。

每个故事目录保存`timing-budget-<编导指纹>.json`；失败时`attempt-*.json`中的修复依据也包含预算。相同失败稿件重用时，实测语速优先于通用估算；文字改写后仍会重新合成并检查，不能把旧语速估算当作实测通过。

## 字数估算、字幕时间与续跑

短片当前目标190秒，最终交付必须120–240秒。初稿的“预计时长”按原声秒数加解说字数/4.5计算，包含标点带来的误差；它不是实际配音时长。草稿估算上限统一保留20%余量（240秒对应288秒），下限保留10%余量，最后仍按真实配音、原声及编码成片严格验收120–240秒。估算超限日志同时列出实际要求和差多少秒，不再仅写“不在范围内”。不能通过放宽成片上限解决草稿问题。

“没有落在画面区间内的字幕证据”表示镜头所引用的对白，既不在当前画面内，也不属于合法的近前文承接或已展示内容。例如镜头结束于954.94秒，引用对白从955.02秒开始；这段旁白是在预借后文。另有编译器按估算裁短旁白、或给原声加前后余量时，可能把原本有效的依据裁出去。现在自动生产保留旁白的选段等待真实配音测量，裁剪和处理余量不能移除唯一依据或切断真实对白。

声纹自动生产在草稿阶段提前拦截夹带未来对白的引用。若只有证据问题，只重写指定旁白及引用，原声、镜头时间和其他文案由程序保留；模型须依据可用对白重新组织必要承接，不能仅换ID保留未证实的断言。若是开场或倒序结构问题，再修对应窗口。草稿不是审核批准：真实配音后仍逐项独立核对人物、事实、画面、场景承接及全部原声；旧入口保留其原有审片。

同一命令续跑会比较当前运行目录保存的失败草稿，优先使用结构完整的版本，避免反复从更差的改稿出发。`draft-resume.json`说明选择依据，`drafts/`、`draft-repairs/`保留草稿和局部修改；覆盖`attempt-*.json`前，原记录保存到`attempt-history/`。这些记录只存在本地输出目录，不进入代码仓库。声纹库、配置、原片的绑定及最终交付审核不变。零成片标记“未产出成片”并以非零退出码返回，不能当作已完成交付。

普通生产命令不变：

```bash
.venv/bin/python -m autoclip produce
```

支持已有的`--subtitle-layer`，使勘误后的对白进入理解、选题和编导。各功能的完整验收状态及剩余问题见[迭代计划](迭代计划.md)。

## 只重试失败选题

当需要检查修复效果，可以读取原批次单集目录的失败选题，在新目录重试：

```bash
.venv/bin/python -m autoclip produce '/path/to/episode.mp4' \
  --config configs.production.toml \
  --retry-rejected-from 'output/原批次/03-素材指纹' \
  --output output/失败选题复核
```

原单集目录必须包含`source.json`、`selection.json`和`rejected.json`，素材必须相同。新批次重新核对当前字幕、故事边界和历史成片重复率；已被其他成片覆盖、证据缺失或无法对应原选题的条目会记录到`retry-selection.json`并显示原因，不会为了凑数选择另一个故事。`--max-new`仍限制本次重试数量。入口处理内容淘汰记录；服务故障继续用原生产命令续跑。

可以同时指定`--subtitle-layer`；保留已完成成片的规则不变。重试需要重新编导、审核和配音，可能产生模型调用费用。

## 接近达标时先局部扩写

真实配音完成后，如果唯一问题是总时长不足、缺口不超过12秒，程序会先检查已有口播的画面余量。只有最多两段现有画面能容纳缺口及约2秒测量余量时，才发起一次局部扩写请求；每个候选还在允许慢放上限内预留0.5秒。不新增镜头、不改变切点、不改原声、不增加字幕引用。

编辑根据内容选择最多两段，补充有依据、能帮助观众理解的解释。空余时间多不代表内容适合扩写；允许明确拒绝。各段字数和秒数只是预算，输出只接受候选段的文字与修改理由，不能顺便更换镜头或整稿。

扩写后重新合成语音，先检查配置范围内的总长（当前新片120–240秒）及每段口播与画面的匹配，再用完整字幕上下文和画面复核事实、人物归属及是否凑字数。审核不通过、返回格式错误、主动拒绝或实测仍不合格时，交回原有有限修复流程；不会直接放行。模型或配音服务故障仍单独报告，不当作内容淘汰。

局部请求与返回保存为`voice-expansion-<轮次>.json`，测量结果保存为`voice-preflight-<轮次>-expanded.json`，语义审核保存为`voice-local-repair-<轮次>.json`。同一轮只提出一次扩写方案，全部请求受本次API调用上限约束。普通`produce`自动执行这一步，不依赖Codex或人工修改稿件。

局部缩写若仍无法匹配画面，报告保留原稿的逐段实测时间、失败镜头、已尝试但放弃的文字修改，以及重新分配相邻完整原声的提示。不会只把一句通用错误交回编导；保留这些信息也不保证下一轮一定能成功，最终仍按有限次数停止。


## 原声优先与局部切点

新片优先保留10–18秒连续精彩原声作为开场，完整句子可延至22秒，再接观点解说。按原片顺序推进，不把后文高潮前置再倒回，也不重复镜头。目标原声占比约60%（通常可参考50%–65%），是创作预算，不是必须补齐的比例。内容足够、总长达到120秒就允许结束；可以补充必要的完整对白与人物反应，不能追加无关过场。

真实配音超出画面时，先搜索相邻未用画面；不足时优先精简口播。两者都无效才尝试在相邻原声的字幕边界重新分配画面，同时保留原声中完整的已识别字幕，不改口播引用、故事范围或镜头顺序。搜索最多同时处理4处超时，保留8个中间组合、最多3个最终候选，先为结尾分配空间。

字幕边界不保证一句话结束，所以候选仍必须经过完整上下文和画面审核，尤其检查移走原声是否破坏铺垫、句意及人物关系。总长不足则只作为待修改候选交回编导；未通过审核不进入渲染。重新剪辑后再次检查历史影片重复率。每轮候选及移走对白保存在`timeline-repair-*.json`，审核在`timeline-review-*.json`，真实复测在`voice-preflight-*-recut.json`。

原声段只保留原片字幕，不叠加“听这句原声”。改变编导、配置或渲染逻辑会生成新的缓存指纹；既有交付影片继续保留。旧片不会自动消除已烧录文字，需要另做新版本才会生效。

## 临时服务故障

模型及配音的429/503等服务错误保留为运行故障，不把稿件判成内容淘汰。模型仍最多3次服务请求，短暂错误等待5、10秒；429默认等待15、30秒，数字Retry-After取更长值、单次最多60秒。Edge 429也等待15、30秒并遵循同样的数字Retry-After上限。成功响应才缓存；不自动切换模型服务商、音色或配音后端。达到重试上限会保存现场并返回失败，同一命令可从缓存继续。

## 字幕画面争议与新增声音

自动审核出现转写同音字、拆字或人物依据自相矛盾时，系统会追加争议字幕所在原片的两帧放大图，重新核对审核意见；局部修稿也读取原片图，不只依据ASR和审核员的转述。图上仅标注字幕ID及时间，不绘制预期文字。原片仍不清楚时保持未知，不能靠更换身份标签放行。核定记录包含这些补充图的内容指纹。

一处语义修订失败不会丢弃同轮其他合格修改；后续整稿仍重新测时并逐项审核。原声单镜头没有足够空间修复切点时，短片允许重新编排相邻窗口，再经过完整测时及审核；仍受原有重试和模型调用上限约束。

短片达到修复上限后，若当前稿件的审核仍有人物声音疑点，自动抽取其引用中适合试听的片段，生成`voice-followup.json`和`voice-followups/`确认资料，唯一人工步骤仍是听声音认角色。只接受与当前原片、字幕、稿件和声纹证据匹配的失败记录，不把旧稿问题当作当前补录需求。未确认声音不写入人工库。

日志会给出`voice-review --output "候选目录"`。完成本轮人工确认后，重跑原制作命令即可：原库先保存到同目录`history/`，系统只合并新增人工具名参考，随后自动重新核对。不需要更换`--library`路径。确认尚未完成时重复制作命令不会继续收费改稿，返回退出码2，已通过的短片仍导出。正式长片尚未接入这一自动补录队列，不能将短片的实现宣称为长片验收。

## 已实配稿恢复与原片字幕核对

短片优先沿用当前运行中与原片、有效字幕、声纹、配置及选题绑定的实配稿。只更新声纹参考时，可从旧运行取回相同来源与配置的稿件作为待审输入，不能复制旧批准。旧核定稿还核对原有来源记录及审核图；其他版本不符、越界或夹带未来引用时拒绝复用。恢复后仍真实测时并完整审核，服务失败不应迫使系统重新编写整个故事。

同一原声切点反复未通过时，系统结合相邻窗口重新编排。窗口前已有原声开场的，窗口必须从旁白开始，避免局部修复再添加原声、破坏既有开场。开场、时长、引用、顺序和独立内容审核继续执行。

标题、角度与钩子每次审核都提供按其用词定位的原片字幕放大图，不等ASR先被质疑才查看。源图指纹绑定核定，缺少这一核对的旧记录重新审核。审核备注里明确要求修正当前稿件时，也须进入问题清单；不能一边判supported，一边将必要纠错藏在notes中。第十集实际发现原片“爵禄”被ASR写作“绝路”，现已自动修正角度说明并重新审核导出。
