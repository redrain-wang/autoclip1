# 口播创作与精修

2026-10-12用户认可加长试片，同时明确要求以后减少审稿式语言。本次成片、封面与最终稿保持不动；这些规则用于后续新稿。

## 首稿的问题来自哪里

此前写稿提示要求动机分析允许另一种解释，比稿又强制正文展示其他解释和证据局限。事实纠错之后，缺少专门面向听众的精修，导致模型把“客观定论、控诉方的推论、单凭问答不能断定”等审核措辞带进口播。限定有时必要，但重复排除、额外猜心与同义总结会削弱观点，也会造成一种错觉：似乎没有审查术语，就没有严谨的分析。

## 新稿规则

- 可见行动直接讲；角色指责用“在田大人的解释里”“他说……”自然交代来源，一次归属覆盖该段分析。
- 来源清楚以后讲机制、选择、压力和代价，不再重复提醒“这不是认罪、未必、证据只到……”；不要求额外补一种心理猜测。
- 关键未知保留，例如谁实际出钱、钱最终去了哪里、是否到账；它们影响结论，不能为了顺口写成已发生事实。
- 对不推进主题的心理猜测直接舍弃，优先分析已出现的行动和角色明确说出的理由。
- 每段增加一个判断，章节递进，结尾回应主问题，避免反复换词解释同一结论。原声已经讲清的动作不再长篇复述。
- 检查真实听感，不能把“客观定论”换成“人格结论”、把“不能断定”换成“没把用意说透”就算完成。

## 程序流程

普通新片：创稿与时间线 → 口播精修及增量核对 → 完整内容/画面审查 → 人物归属检查 → 实际配音测时及必要修稿 → 渲染前检查实际口播。

长篇提纲：分章写稿 → 全稿口播精修及增量核对 → 保存尚未审片的计划 → 配音测时 → 逐段开发核对 → 固定稿渲染。当前长篇仍是开发核对路径，不能宣称新精修等于全自动内容验收。

`configs.production.toml`、`configs.long.toml`和示例剧配置启用`oral_edit=true`。基础Settings保留关闭值供已有集成兼容；采用项目提供的生产配置即可启用，无须Codex在旁补改。固定稿`render-sample`不会自动执行新精修，继续遵守已有审核绑定。

精修只能提出原有narration.text的改动；标题、角度、原声、镜头顺序、时间码和证据ID都不能改，每段文字控制在原段65%–120%。该范围只防止精修变成大幅重构，不代替实际配音时长验收。

最多两轮提案，每轮另发一次改动核对，最多增加四次模型请求。核对分开记录新增事实错误、旧稿已有疑点和听感问题。旧疑点不伪称是换词造成，也不能当作已解决，须交给后续完整内容审核。若事实或听感仍不通过，保存失败提案并停止，不删除限定强行出片、不转用其他收费接口。

检测到明确审查措辞时会要求自然重写，不做字符串删除。精修与修稿共用写作规则；配音后再次检查实际使用的文字，避免时长修复把审核腔补回来。所有模型提案与核对记录保存在忽略的运行目录，不包含密钥。

## 本轮验证的边界

真实Go Flash测试发现，旧稿精修会只换词、继续附带无益猜心；程序已按两轮上限拒绝这类提案。定向短语检测归零，只说明显眼术语消失，不能当成精彩程度的证明。因此另检查改写段的来源、重复限定与听感，不依赖词频自动评分。

测试同时覆盖原声/时间码/证据不变、错误修稿拒绝、有限重试、真实未知保留，以及短片与提纲写稿接入。下一条新片仍需用实际成片验证观点递进和听感，不能保证每次模型稿都精彩。
